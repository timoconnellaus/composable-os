Screens a shipped pack declares are built into the admin and shown to whoever could call every tool in `opens`. Blocks are the pack's screens for client apps, copied with `cos add`.

## Staff screens

This pack declares no staff screens.

## Blocks

| Block | Skin | What it shows |
| --- | --- | --- |
| [ticketing-checkout](/reference/blocks/ticketing-checkout/) | web | Choosing tickets and paying, for a site (stage 27): quantities per ticket type, pay in full or by deposit when every chosen type offers one, then the payment provider's page. |
| [ticketing-events](/reference/blocks/ticketing-events/) | web | The events on sale, and one event's details, for a site's events page (stage 27). |
| [ticketing-my-tickets](/reference/blocks/ticketing-my-tickets/) | web | A signed-in customer's tickets, for a site (stage 27). |
| [ticketing-native-my-tickets](/reference/blocks/ticketing-native-my-tickets/) | native | A signed-in customer's tickets, for the mobile app's Tickets tab (stage 27). |
| [ticketing-native-scanner](/reference/blocks/ticketing-native-scanner/) | native | The door scanner, for the staff app (stage 27): the camera reads a code, the host checks it in, and the screen says clearly let in or not and why, with a haptic, and counts who was let in on this device. |
| [ticketing-native-ticket](/reference/blocks/ticketing-native-ticket/) | native | One ticket with its code, for the mobile app (stage 27): a QR carrying the code alone, large on a white card, with the screen at full brightness while it is shown and as it was afterwards. |
| [ticketing-order](/reference/blocks/ticketing-order/) | web | The page the buyer comes back to from the payment provider (stage 27). |
